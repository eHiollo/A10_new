## 自动记录内容

每次启动产生 `client/logs/run_*/`：

- `bridge.log`：启动、连接、policy 启停、异常及重试。
- `events.jsonl`：启动参数（排除 API key）、源码摘要、控制器构建时间、模型 metadata、每批观测及完整动作、回包形状、推理往返耗时、发送应答与批次号、裁剪数量、队列状态。
- `policy_right.png` / `policy_top.png`：首次实际送入模型的 RGB 图像，已做旋转和 224×224 缩放补边；没有 top 时不产生 top 图片。
- 每约 100ms 的控制器采样：指令和反馈、关节速度参数、周期/执行耗时窗口最大值。`sample.q0` 为指令，`sample.actual` 为反馈；手臂前六维可相减分析跟踪误差。
- `segment` / `retarget`：`q0` 为衔接起点，`q1` 为新目标，`actual` 为此时反馈。
- `align` / `threshold_skip` / `start` / `stop`：前缀裁剪、动作阈值拒绝和计划启停。

控制器使用固定容量内存缓冲记录诊断，经状态查询取出并由 Python 写盘；实时线程不再写/flush CSV。`trace_dropped` 显示缓冲满或锁竞争时丢失的诊断数量。多个客户端同时查询状态会分走事件，诊断时保留一个 bridge。


新增可选 `--mode pipeline`：

1. 控制器每约 50ms 按当前指令、剩余全部关节/夹爪目标和实际限速估算剩余执行时间，状态字段为 `remaining_time_s`；并非把队列步数简单除以 30。
2. bridge 在预计还剩约 0.45 秒时采观测并开始推理。提前量根据最近 20 次有效推理的 P95 加 0.05 秒更新，并受预测 horizon 限制。
3. 结果提前到达就等待批末，旧队列清空后立即发送，不再等待额外 settle。结果来晚仍然会有短暂停顿，日志会记录。
4. 入队附带旧批次号，控制器在同一把锁中确认批次未变且队列为空，才接受衔接。等待期间 stop、重启、别的客户端换批次或预测已经过期，会丢掉旧预测重来。
5. policy 没运行时，bridge 仍可常驻取图和推理。旧控制器没有执行时间估计时，pipeline 会告知并退回等队列清空再推理，不会因该字段缺失退出。

需要重新启动本轮编译的 `build/kaanh_rtc/bin/kaanhbin`，bridge 终端使用：

```bash
conda activate client
cd /home/kaanh/A10_new/client
python run_bridge.py --policy-host 192.168.110.119 --policy-port 8000 \
  --robot-host 127.0.0.1 --robot-port 8080 --mode pipeline
```

控制器终端仍输入 `policy`，没有 `--mode` 参数。`--prefetch-lead` 可调整初始提前量，默认 0.45 秒；`--hz` 对 pipeline 不起作用。原有 async/sync 保留，默认模式仍是 async。

新增日志事件 `pipeline_prefetch`、`pipeline_send`、`pipeline_discard`；汇总增加 `queue_empty_to_next_send_ms` 和 `batch_execution_s`。本轮保留绝对目标及现有限速，不对动作额外叠加当前位置。预取时仍有观测延迟，是否还有批末回拉、停顿能减少多少需要新一轮实机确认。

- 队首读取/弹出绑定批次号，旧批次不能弹出替换后的新队首。
- 换段从上一拍实际下发的插值指令衔接；插值拍数补齐，避免 `n-1` 分母使速度超过设置值。
- 过期前缀包含接收后的等待时间；整段过期全部丢弃，超过 5 秒的年龄不再置零。
- 非法维度/非有限动作整批拒绝，不再跳过单个元素后把剩余元素错位拼成关节指令。
